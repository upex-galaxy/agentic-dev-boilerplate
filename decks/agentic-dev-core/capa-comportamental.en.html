The behavioral layer

Butler Pattern, PM Voice and Visual Mapping explain why the repo answers the way it does. Before them comes another question: when two layers have an opinion on the same thing, which one wins? The answer is in AGENTS.md §2. Each layer rules over a single dimension, and a hook repeats the contract on every turn so that the layer that happens to repeat most does not win by accident.

01Two layers, two dimensions

Each layer rules over a single dimension. If two claim the same one, they contradict each other, and the tiebreak ends up mechanical instead of deliberate.

Layer Dimension Where it lives Frequency
AGENTS.md §2rules what is said, granularity and register Butler + PM Voice + Visual Mapping every turn, via personality-reinject.mjs
Reply rules and humanizer how it looks and what texture it has the reply rules (## Replies) in the user-level agent instructions (~/.claude/CLAUDE.md in Claude Code), and the humanizer skill at session start; its summary travels in the contract of every turn
Rule
§2 always wins on content. The reply rules only decide the rendering (headings, bold anchors, backticks, tables, spacing), and the texture of the sentences (no long dash, varied length, no closing recap) comes from humanizer. If a rule from those sources changed what is said, it is misplaced and belongs in §2.
The risk
Without reinjection, the tiebreak would be mechanical, not editorial. A §2 read once at startup fades as the context grows, while anything a plugin reinjects on every UserPromptSubmit stays fresh. The most repeated layer would win, not the one that is right, and PM Voice would evaporate in long sessions. That is why §2 travels on every turn. Concision has no layer of its own: it comes from §2, from the reply rules and from humanizer, with no communication-mode plugin (critical rule #11).

03The §2 rules, one per card

The session above shows three of them in action. §2 has more: how the agent reasons before touching code, and which instrument it uses to ask the human to decide.

Think before coding

Think before coding

Explicit assumptions. If there are several readings, they are presented, and none is picked in silence. If a simpler path exists, it is said; if something is unclear, the agent stops and asks. An exploratory question gets a 2-3 sentence recommendation with its main tradeoff, not an implementation.

Simplicity first

Simplicity first

The minimum code that solves the problem: no features or single-use abstractions, no "flexibility" nobody asked for, no handling of impossible errors. The scaffold architecture does not count as speculative abstraction (api/, schemas/, db/, the design system structure).

Surgical changes

Surgical changes

Touch only what is needed and respect the existing style. Unrelated dead code is mentioned, not deleted; imports that the change itself left unused are removed. Regenerative commands are exempt, because regenerating is the task.

Goal-driven execution

Goal-driven execution

First the success criterion, then the loop until it is verified. "Add validation" becomes "tests for the invalid input, and make them pass". Each step of a plan carries its observable verify:: a test that passes, a file that exists, an exit 0.

Butler pattern

Headline first, then the menu

The headline answers the literal question and stands on its own. Below it, each remaining topic as an atomic bullet topic: fragment, never grouped into broad categories: twelve specific bullets are worth more than three buckets. No artificial cap, and never a long dash as a separator.

PM Voice

The headline tells the value, not the action

It is written for a PM, PO or tester, with no hook phrase up front. It is suspended for one turn when the message carries paths, commands or errors, when technical detail is requested, or when the topic touches security, auth, RLS, migrations, rollback or a deploy to production. If the change affects data integrity, measurable performance, security or rollback, the headline adds one line of technical impact.

Visual mapping

What can be mapped gets drawn

Tables to compare, ASCII flows for sequences, trees for hierarchies, boxes for components, state machines for lifecycles. The visual replaces the prose, it does not decorate it, and it is skipped in single-concept answers. When unsure about the terminal, plain ASCII.

Asking the human to decide

The instrument follows the shape of the question

Small decisions, few or many, are swept at the end of the turn with the harness's own question tool, in batches until done. Heavy ones (architecture, an approach, a big change, a tradeoff that does not fit honestly in two sentences) go to the mkd decision deck: each option with its value and cost, at most one recommended, with the why. Without mkd installed, one line offering it and the sweep goes on.

04How it holds on every turn

The contract lives in one place and reaches each harness through a thin adapter. bun run agents:compat:check ties each adapter to the emitter, so the text cannot diverge between hosts.

Piece What it does
Emitter .agents/hooks/personality-reinject.mjs builds the context of each turn: the output contract (§2 plus the user's reply rules), the AGENT IDENTITY: line with the worktree, session and harness that the commit trailers copy, an ORCA: line only if the orca binary is reachable, the ROUTE: and ROUTE-OPTIONAL: lines with the instruction sections the prompt needs, and at most one setup notice (checkout without .env, or a worktree without bun run worktree:provision).
Claude Code .claude/settings.json declares the UserPromptSubmit hook that runs the emitter. It also runs it on SessionStart with compact or clear, to re-arm the lines, and on PostToolUse, where it only warns with ROUTE-PENDING: if a route was left unread.
Codex .codex/hooks.json declares the same UserPromptSubmit hook, and SessionStart with compact or clear.
Pi .pi/extensions/agentic-dev.js hooks into the same emitter: identity line, ROUTE: lines, ROUTE-PENDING: from tool_result and re-arming on session_compact. It only loads in a trusted folder (/trust).
OpenCode .opencode/plugins/personality-reinject.js imports the same lines and pushes them into the system prompt.
Heads up
The instructions are not a style model. AGENTS.md, docs/ai-personality.md and each SKILL.md are dense prose that machines read. In chat, the agent does not imitate their typography, their density or their arrows. docs/ai-personality.md is the human mirror of §2 and is edited together with it.
