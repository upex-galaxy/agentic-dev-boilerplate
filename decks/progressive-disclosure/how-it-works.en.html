agentic-dev-core · progressive disclosure

Instructions, in layers

The agent does not need every rule in the repo on every turn. It always needs the ones that bind it, and the rest when the request calls for them. That is why AGENTS.md is a small core that loads in every session, each topic lives in its own file under .agents/instructions/, and a fixed router, backed by a hook, says which one to read and when.

AGENTS.md · L0 .agents/instructions/ · L1 .agents/hooks/personality-reinject.mjs scripts/lint-instructions.ts ADR-0009

01Why split the file

Before, AGENTS.md was a single file that every session loaded whole, needed or not. It had two costs, and the second one was invisible.

Visible cost

Every session paid for the whole file

A chat about a color paid for the git policy, the Jira cache and the multi-harness contract. Conditional sections always loaded, even though most sessions never used them.

Invisible cost

Codex cut it in the middle

Codex merges the project's AGENTS.md files into a single budget, project_doc_max_bytes, and cuts the text at the byte that crosses it, with just a warning in the log. The old file went well past it: in Codex, everything after the cut never reached the model.

What did not work

An import saves nothing

In Claude Code an @file is expanded whole at startup, and neither OpenCode nor Codex expands imports. The only lazy thing all hosts share is the model reading a file because an instruction told it to, skills, and a hook that injects text into every request. The design uses those three things.

02Three layers

Each layer loads at a different moment. L0 is always there; L1 comes in on request, one section per topic; L2 is what already existed, each skill's references/.

The arrows are on-request reads: L0 never imports a section. The ones the drawing shows are examples; the real list is the folder.

Layer File When it loads
L0 AGENTS.md every session, on every host. Claude Code arrives through CLAUDE.md, which is exactly @AGENTS.md plus a newline
L1 one file per section in .agents/instructions/ on request: the L0 router says when to read each one, and the hook reminds it with a ROUTE: line
L2 each skill's references/ on request, named by the section or skill that needs them
Name
Progressive disclosure is the term Anthropic uses for the skills mechanism (the description at startup, the body when used). This extends it to project instructions. There is no new L2 layer: each section already had its depth in the references/ it cites.

03The fixed router

A table in L0, between <!-- router:start --> and <!-- router:end -->, with three columns: Kind, Load and Also. The rows are request types, not features, so the table does not grow with the project: the section and its triggers: grow. A lock enforces the fixed part: the comment <!-- router:lock <fingerprint> <ADR-NNNN> --> stores the fingerprint of the table and the ADR that decided it, and any row change fails until an ADR covers it.

Column What it says Example (git row)
Kind the request type that triggers the row git: branch, commit, push, PR, merge, conflict
Load the files to read, as paths in backticks; the first one is the anchor of the row .agents/instructions/agent-git.md
Also the skill or file loaded together git-flow-master
One table only
The hook reads this same table on every request, along with the frontmatter of each section. There is no generated copy: the table the model reads and the one the classifier uses cannot diverge. The real list of rows is in AGENTS.md; this deck does not copy it.

04The LOAD PROTOCOL

Four lines in the L0 header turn the router into an obligation. Without them, the table would be a suggestion.

  1. Before acting, the request is compared against the router and every file that matches and is not yet in the conversation is read.
  2. A ROUTE: line injected by the hook is binding and wins over the model's own judgment: its file is read before acting. A ROUTE-OPTIONAL: is not binding (one of its files is read only if the task needs it) and a ROUTE-PENDING: names a binding file that is still unread.
  3. A file already read is not re-read, unless a compaction removed it from the context. When in doubt, read: sections are small; a skipped section is exactly the failure this design avoids.
  4. A section is edited in its own file, never by pasting its prose into AGENTS.md. A rule that only this project has goes to .agents/instructions/agent-project.md.

Below those lines, a separate paragraph says skills and sections are loaded by meaning in any language. The triggers are in English, so in another language a ROUTE: line can be missing or arrive incomplete, and the agent routes on its own from the router.

05The hook and the ROUTE: line

The router in L0 depends on the model consulting it. The hook does not: it classifies every request with code and writes down what to read. It is the same emitter that already put the output contract and the AGENT IDENTITY: line.

# one line per new file, after AGENT IDENTITY: and ORCA:
ROUTE: read .agents/instructions/agent-git.md (git, <n> lines) before acting on this prompt
ROUTE: read package.json (<n> lines) before acting on this prompt
# what went past the cap, in a single line that does not bind
ROUTE-OPTIONAL: the prompt also touches .agents/instructions/agent-harnesses.md (harnesses); read one only if the task needs it.
Rule What it does
Anchor A row fires when the request matches the first file of its Load column; then every file of the row is routed. That way a file shared by two rows does not drag in the other row's files.
Triggers Each section declares in its frontmatter triggers: (case-insensitive regex, in English and Spanish) and paths: (repo prefixes). Tuning the routing means editing those lists, never L0.
Scope A ROUTE-SCOPE: line in the request replaces the request for classification: each item is a section id (routed directly) or words (they are classified); none routes nothing. Without it, a request that carries an orchestrator's preamble is classified only by the task block that follows its marker. Absolute paths are neutralized first: a folder's name is not an intent.
Ranking and cap Fired rows are ordered by the strength of their anchor (an id from the scope, then paths: hits, then distinct triggers, then the earliest match). Only the first MAX_ROUTED_SECTIONS sections get a binding ROUTE:; the rest go to a single ROUTE-OPTIONAL: line. Measured: an agent reads a lone route far more than one of five in the same turn (ADR-0018).
Reminder (Claude Code) A PostToolUse hook runs the same emitter: the first tool that reads no routed section, while one is still unread, gets ONE ROUTE-PENDING: line. It does not repeat within the turn and stays silent for subagents.
Dedupe per session A state file in the system temp, per checkout and per session, remembers what was routed. A request that needs nothing new adds nothing.
Re-arming after compaction or /clear A SessionStart with matcher: "compact" or matcher: "clear" runs the emitter again, which clears the state and prints nothing: whatever the compaction or the /clear removed from the context is routed again the next time it is needed.
Host How the line arrives
Claude Code .claude/settings.json: UserPromptSubmit runs the emitter; SessionStart with compact or clear re-arms it; PostToolUse with no matcher reminds about an unread route.
Codex .codex/hooks.json: the same, only in a trusted project whose hooks are trusted too (codex exec skips an untrusted hook silently).
OpenCode 1 .opencode/plugins/personality-reinject.js classifies in chat.message, pushes the line into the system prompt and re-arms only on compaction (it does not register anything for /clear).
OpenCode 2 The same plugin classifies in the session prompt hook, pushes the line through the context hook and re-arms in the compaction hook.

A prompt that starts with <task-notification> (the harness notice that a background subagent finished), or that carries only harness blocks such as <system-reminder>, routes nothing and does not touch the routing state: nobody asked for those routes.

06Critical rules: the binding sentence, and the full text apart

A rule that binds has to be where the agent always reads. But its rationale, edge cases and mechanics do not need to occupy every turn.

# each rule in L0: its binding sentence, verbatim, and a pointer
6. **Quality verification**: After code changes, verify in this order: tests, then types, then lint. Run all three; skip none. Full: agent-critical-rules.md#6
In L0

The binding sentence, verbatim

Each rule keeps its binding sentence, word for word, with the same number and name. No rule loses force: what binds still loads in every session.

In L1

The full text in one file

.agents/instructions/agent-critical-rules.md has each rule under ## N. NAME, with its rationale and edge cases. The router has a row to read it when the agent is about to break a rule, is unsure, or is asked about it.

When editing

Two places, on purpose

Changing a rule means touching its full text in agent-critical-rules.md and its sentence in AGENTS.md, which has to stay verbatim. bun run instructions:check compares the two.

07Two imports for Claude, a reinforced instruction for the others

package.json and .agents/project.yaml are the two data files most often consulted. The router rows that name them do two things at once.

Host What happens
Claude Code The row writes @package.json and @.agents/project.yaml as plain text, without backticks: Claude Code expands an import at startup and skips the ones inside code. Both files enter the session whole.
OpenCode and Codex They do not expand imports. They read the reinforced instruction in the same row ("whenever any of these apply, read ...") and open the file when the condition is met.
Cost
In Claude Code, imports always load, so they add to the start of the session even though they do not count against the L0 budget, which measures the file itself. The measurement in bytes and tokens is in .context/ADR/ADR-0009-progressive-disclosure-of-instructions.md. bun run instructions:check rejects any other stray @ in L0: the allowed list is ALLOWED_IMPORTS in scripts/lint-instructions.ts.

09How to edit

The sections are shared doctrine: bun sync keeps them up to date with the boilerplate. agent-project.md belongs to each project and no sync touches it; a project that does not have it gets it once from .agents/instructions/agent-project.md.template. The golden rule: text goes to the owning file, never back into AGENTS.md.

I want to change Where
the detail of a topic its file in .agents/instructions/
when a section is routed its triggers: and paths: in the frontmatter
a critical rule its text in agent-critical-rules.md and its verbatim sentence in AGENTS.md
a rule that only this project has .agents/instructions/agent-project.md
a line with NEVER or MUST in a section it has to name who holds it when the section is not loaded (a critical rule, a skill's Compact Rules) or be declared local with <!-- binds-in-section: <reason> -->
CLAUDE.md nothing: it is the generated shim (Critical Rule #15)
Gate
bun run instructions:check checks budget, router, frontmatter, rule sentences, who holds each NEVER or MUST, and imports. It runs inside bun run repo:check. It also holds three locks (.context/ADR/ADR-0014-instructions-maintenance-locks.md): the router pinned to its ADR (--accept-router ADR-NNNN records a new decision), the evaluation of the classifier against the labeled prompts on every run, and every section coming complete (frontmatter, router row, its own prompts). The other half is measured by bun run instructions:audit: of the routes the hook injected, how many the agent actually read. The full editing guide is in .agents/instructions/README.md.

10Budgets

L0 has a ceiling because Codex cuts without warning. The values are named constants in scripts/lint-instructions.ts, pinned by .context/ADR/ADR-0009-progressive-disclosure-of-instructions.md: changing one is a new decision, with its ADR.

Level Constant If exceeded
Target L0_TARGET warning: some detail could live in a section
Ceiling L0_BUDGET error: the boilerplate's L0 does not fit
With project additions L0_PROJECT_BUDGET error: the project's text goes to agent-project.md or a context skill
Codex cap CODEX_PROJECT_DOC_MAX_BYTES always an error, whatever the others say: it is the default value of project_doc_max_bytes
Heads up
The target warns on purpose. §2 comes in whole by the owner's rule, and that leaves L0 above the target and below the ceiling. The warning stays visible so nobody adds text to L0 without thinking. The current size is printed by bun run instructions:check.

11How we measure that it works

Two different questions: whether the classifier routes what it should route, and whether the model then reads what was routed to it.

What is measured Where
Recall, binding recall and precision of the classifier Requests labeled by hand, in English and Spanish, in cli/lib/fixtures/instruction-router-eval.json; the thresholds are its targets field and cli/lib/instruction-router.test.ts checks them inside bun run test. Binding recall counts only the ROUTE: lines (the cap must not have pushed an expected section into the optional one) and so does precision: an optional line binds nothing.
That it is not slow the same test requires routing a request to stay well under 50 ms
That hook and lint read the same scripts/lib/hook-router-parity.test.ts ties the hook's parser to that of scripts/lib/instructions.ts
That the model obeys transcript audit: every ROUTE: should be followed by a read of the routed file before the first action; it also counts how many reads followed a ROUTE-PENDING:
If it fails
A request that does not route what it should is fixed in the section's triggers:, and the request goes into the labeled set so it does not happen again. Relabeling to hide a false positive does not count.
